# Design Tokens Integration Guide

## Overview
This guide documents the integration of design tokens generated via Specify CLI into the multi-tenant appointment booking platform. Tokens ensure consistent theming across tenants, integrating with Tailwind CSS for styling. This aligns with the [Design Tokens (Specify) v1.0 spec](docs/specs/design-tokens-specify-v1.0.md), focusing on freemium tools and Supabase storage for tenant isolation.

## CLI Usage
Specify CLI generates tokens from Figma designs or prompts. Install via npm:

```bash
npm install -g @specify/cli
```

### Generate Tokens
Run the following command to generate tokens using the config:

```bash
npx specify generate
```

- **Input**: `./design-tokens.fig` (Figma file) or prompt-based.
- **Output**: `./tokens.json` (JSON tokens), `./design-tokens.scss` (CSS vars), Tailwind config extensions.
- **Themes**: Supports light/dark modes as defined in `specify.config.json`.
- **Customization**: For tenant-specific tokens, run per tenant: `npx specify generate --theme tenant-name`.

After generation, commit tokens to repo or store in Supabase for runtime loading.

### Build Integration
1. Run `npx specify generate` during build (add to `package.json` scripts: `"generate:tokens": "specify generate"`).
2. Deploy: Tokens are bundled in Next.js build; for dynamic loading, fetch from Supabase via RLS.

## Tailwind Config Integration
Extend `tailwind.config.ts` to consume generated tokens. Use the Tailwind transformer output for dynamic theme extension.

### Snippet for tailwind.config.ts
```typescript
// tailwind.config.ts
import type { Config } from 'tailwindcss';
import { tokens } from './tokens.json'; // Generated by Specify

const config: Config = {
  content: [
    './pages/**/*.{js,ts,jsx,tsx,mdx}',
    './components/**/*.{js,ts,jsx,tsx,mdx}',
    './app/**/*.{js,ts,jsx,tsx,mdx}',
  ],
  theme: {
    extend: {
      colors: {
        // Map Specify tokens to Tailwind
        primary: {
          50: tokens.colors.primary[50],
          100: tokens.colors.primary[100],
          // ... extend for all shades
          DEFAULT: tokens.colors.primary.DEFAULT,
        },
        // Tenant-specific: Load dynamically if needed
        tenant: {
          primary: 'var(--tenant-primary)', // CSS var from Supabase
        },
        // Dark mode
        dark: tokens.modes.dark.colors,
      },
      fontFamily: {
        sans: [tokens.fonts.sans, 'ui-sans-serif', 'system-ui'],
        // ... other fonts from tokens
      },
      spacing: tokens.sizes, // e.g., { xs: '0.25rem', sm: '0.5rem' }
      // Shadows, borders, etc. from tokens
    },
  },
  plugins: [
    // Optional: Plugin to inject CSS vars at runtime
    function ({ addBase }) {
      addBase({
        ':root': {
          // Light mode vars
          '--primary': tokens.colors.primary.DEFAULT,
          // ... all vars
        },
        '[data-theme="dark"]': {
          // Dark mode vars
          '--primary': tokens.modes.dark.colors.primary.DEFAULT,
        },
      });
    },
  ],
  darkMode: 'class', // Or 'media' for system preference
};

export default config;
```

### Dynamic Tenant Loading
For multi-tenant, fetch tokens from Supabase in a provider:

```typescript
// In components/theme-provider.tsx (see integration snippet below)
import { createClient } from '@supabase/supabase-js';

const supabase = createClient(...);

export async function loadTenantTokens(tenantId: string) {
  const { data, error } = await supabase
    .from('design_tokens')
    .select('*')
    .eq('tenant_id', tenantId)
    .single(); // RLS enforces isolation

  if (error) {
    // Fallback to default tokens
    return defaultTokens;
  }
  return data.tokens;
}
```

## Security Notes
- **RLS**: Supabase queries filter by `tenant_id = auth.jwt()->>'tenant_id'` to prevent cross-tenant access.
- **Validation**: Sanitize token values server-side to avoid CSS injection.
- **Storage**: Store tokens in Supabase `design_tokens` table with encryption for sensitive values.

## Testing
- **Jest Snippet** for token validation:
```typescript
// __tests__/tokens.test.ts
import { tokens } from '../tokens.json';

describe('Design Tokens', () => {
  test('Tokens have required structure', () => {
    expect(tokens.colors.primary).toHaveProperty('DEFAULT');
    expect(tokens.modes).toHaveProperty('dark');
  });

  test('Contrast ratios meet AA standards', () => {
    // Use a library like @accessible/contrast-checker
    const checker = new ContrastChecker();
    expect(checker.contrast(tokens.colors.primary.DEFAULT, tokens.colors.background.DEFAULT)).toBeGreaterThan(4.5);
  });
});
```

Run: `npm test -- tokens`.

This integration ensures theme consistency without full rewrites, compatible with Next.js 14 and existing Clerk/Supabase setup.
